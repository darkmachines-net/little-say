# Card pictures

Automatic pictures check the meaning of every card and whether neighboring pictures can be confused. Automatic keeps each accurate, unambiguous emoji, searches the library only for gaps, and generates an illustration only when a gap has no suitable library match. A single gap never promotes the whole board to illustrations, including on boards with legacy `consistent: true`. Different language labels for the same meaning can share a picture.

## Parent controls

Settings defines the source defaults for new boards. Automatic includes generation for gaps. Sending a prompt or starting a voice prompt immediately starts that action; there is no AI opt-in interstitial or separate picture-permission switch. The legacy `aiConsent` field records explicit AI use for existing background-audio and editing behavior. Library only and Emoji only never request image generation. The older stored `autoImages` flag remains readable for compatibility but no longer gates Automatic. Server capabilities and `AAC_IMAGE_GENERATION=false` still govern availability. The conversation introduces what is sent to AI without blocking input. Source controls explain server API use.

**Build manually** starts directly from the boards screen, separately from **New board**. Conversation suggestions only fill the message field; they never switch creation modes. New board and Edit with AI open a full-page workspace. Browser routes use `#boards/new` and `#boards/<id>/ai`; Back cancels active work, and reloading opens a fresh conversation for that source without saving a partial draft. The conversation and independently scrolling board canvas sit side by side on tablets/desktops and stack on phones. Clarification preserves the current canvas. Downloaded pictures appear as each finishes; queued, active, ready, and emoji-fallback cards have distinct states. Active cards animate unless reduced motion is requested. The board is saved only through the final apply action.

Picture instructions can be given in the message or in **Picture settings**, available from the page header even while work runs. Source changes during a request apply to the next update, never silently changing active jobs. Picture source is one labeled selector with descriptions; selecting a choice or pressing Escape restores keyboard focus. Picture protection uses a separate switch; the old consistency switch is no longer shown. There is no illustration-style selector: new picture work always requests simple color, while existing saved artwork remains intact.

Completed drafts go straight to save or refinement without suggesting AI illustrations. Parents who want different artwork can choose **AI illustrations** in **Picture settings**, then **Update draft pictures**. Unresolved gaps retain the existing fallback summary. Protected photos and card source overrides remain respected.

Use **Update draft pictures** after adjusting conversation controls. Board **Pictures** offers **Improve pictures** and **Restyle board**, with a preview and explicit apply. In each card, **Picture options** supports library search, picture descriptions, source overrides and generation. An inherited card source shows the current board choice. **Keep this picture** protects an individual choice. Library search and selection work without an OpenAI key.

Board defaults apply unless the card overrides them. Explicit prompt changes update the draft; unrelated text edits preserve pictures. Photos and protected choices are excluded from board-wide replacement. Explicit card replacement can replace them. Saving a changed, unprotected card after prior explicit AI use stages a board preview before applying picture changes. Closing the preview discards that staged card edit.

Failures do not buy another generation automatically. Missing matches, unavailable generation, failed downloads, and rejected new pictures use the best analyzed emoji (or the original emoji when analysis is unavailable). Existing asset-backed pictures remain after failed replacements. One concise board summary explains fallback without repeating technical errors for every card. The board stays usable and can be saved; parents can revise individual pictures later. Child play never starts network work or replaces pictures.

Account compatibility: board picture policies, card source overrides, protection, descriptions, and saved picture references travel with the complete board snapshots introduced in [PR #9](https://github.com/MChartier/little-say/pull/9). This refinement adds no persistent settings. Device-wide picture defaults remain local under that sync contract; temporary draft progress and conversation state are not synced.

## Sources and licensing

The committed metadata catalog is generated by `npm run pictures:update` from these fixed revisions:

- [Mulberry Symbols](https://mulberrysymbols.org/), `9cbab9f400c5de44e2bc58839cca07294aadb086` (v3.6.1): color illustrations by Steve Lee.
- [OpenMoji](https://openmoji.org/), `f9fc506a3f913be9897ab0181d611d4c910a4104` (17.0.0): black artwork by HfG Schwäbisch Gmünd and contributors.

The current app searches the color catalog. Outline entries and their style metadata remain readable for compatibility with earlier picture drafts; they are not offered as a user-selectable style.

Both artwork sets use [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/), permitting commercial reuse with attribution and applicable share-alike terms. Each asset retains its author, original source URL, license, and rasterization/padding notice. Credits are available in settings and card details. Original vector artwork remains available at each pinned source URL; adaptations must retain the artwork license. Catalog metadata is generated data; its importer owns documentation and revision updates.

The backend fetches only URLs from that catalog, disallows redirects and external SVG resources, validates image sizes, then rasterizes to PNG. It serves cached PNGs from its own asset endpoint. First use of an uncached symbol requires server internet access to GitHub. Saved boards need neither GitHub nor the home server for offline pictures.

## API and persistence

`/api/health` advertises picture protocol version 1 and catalog, analysis, and generation capabilities. Clients opt into extended board proposals with `pictureCapability: 1`. Legacy clients receive the original emoji proposal shape; clients talking to old servers retain the legacy flow.

Picture endpoints provide catalog search (`GET /api/pictures/search`), a chosen symbol (`GET /api/pictures/library/:id`), concept analysis (`POST /api/pictures/analyze`), durable jobs (`POST /api/pictures/jobs`, `GET /api/pictures/jobs/:id`, `POST /api/pictures/jobs/:id/cancel`), immutable PNGs (`GET /api/pictures/assets/:digest.png`), and final board review (`POST /api/pictures/review`). Schemas live in the shared core. Optional job `phase` distinguishes library lookup (`finding`) from image generation (`generating`); old servers without it show generic picture improvement. Progress counts only targeted cards and leaves other pictures in place. Job identity binds a UUID to its payload and draft/card identity; changed payloads cannot reuse an ID. Cancellation stops queued work and attempts to abort active generation; a provider may already have charged for work underway. Restarted unfinished jobs require an explicit new attempt.

Library format v2 migrates v1 without changing board appearance. Native PNGs are separate from cropped JPEG photos; browser PNGs use IndexedDB v3. Downloads are digest-verified before references can be saved. Pruning runs at initial load and retains board and starter-draft assets; active drafts and undo are never pruned mid-session.

`OPENAI_IMAGE_MODEL` defaults to `gpt-image-2.5-flare`, using medium-quality 1024-square transparent PNG output. `AAC_IMAGE_GENERATION=false` disables new server-side generation. `PICTURE_CACHE_DIR` defaults to `.cache/pictures` for workspace development and `/app/data/pictures` in Docker, with its own persistent volume. Generation concurrency is two; the queue holds at most 48 pending cards. No model keys reach the client.

Generated pictures and their concept descriptions, completed job metadata, and hashed cache keys remain in the private server cache with no automatic eviction. Personal photos and their paths are excluded from AI requests. Optional [account sync](ACCOUNTS.md) uploads photos and saved illustrations to a separate authenticated backup without local paths. Requests and provider response bodies are not logged. Image-generation endpoints retain the app's private-network, unauthenticated deployment boundary. Do not expose them as a public image-generation service.

## Validation

`npm run check` and `npm run test:web` exercise mocked matching/generation, retention, migration, permissions, cancellation, failed downloads and offline play. `npm run eval:pictures` runs billable concept/library checks on six construction vehicles; add `-- --generate` to permit up to six new generated pictures. `npm run eval:pictures -- --animals --generate` creates a matching six-animal comparison: downloaded Mulberry library artwork, emoji, and deliberately requested AI illustrations. Results and a contact sheet are written under ignored `artifacts/picture-evaluation/`. The screenshot script captures all three sources with identical animal labels. Inspect the actual pictures: model review is fallible, and tests cannot establish a child's understanding or physical-device performance.
