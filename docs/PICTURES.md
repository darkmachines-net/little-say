# Card pictures

Automatic pictures check the meaning of every card and whether neighboring pictures can be confused. Accurate emoji remain when they cover the board. Otherwise, consistent mode uses simple color illustrations for the automatic set. Different language labels for the same meaning can share a picture.

## Parent controls

Parent settings defines defaults for new boards and permission for automatic AI pictures. That permission starts off. Library matching uses the existing AI consent; generating images also requires picture permission and the server capability. Enabling picture permission discloses paid API use and server retention. Per-draft permission does not change the device default.

New board and Edit with AI accept picture instructions in the message and show the resolved settings in **Picture settings**. Picture source is one labeled selector showing the current choice and its explanation. Opening it reveals a vertical list with an explanation for each source; selecting an option or pressing Escape closes it and restores keyboard focus. Consistency, generation permission, and picture protection use separate switches. There is no illustration-style selector: new picture work always requests simple color, while existing saved artwork remains intact.

Use **Update draft pictures** after adjusting conversation controls. Board **Pictures** offers **Improve pictures** and **Restyle board**, with a preview and explicit apply. In each card, **Picture options** supports library search, picture descriptions, source overrides and generation. An inherited card source shows the current board choice. **Keep this picture** protects an individual choice. Library search and selection work without an OpenAI key.

Board defaults apply unless the card overrides them. Explicit prompt changes update the draft; unrelated text edits preserve pictures. Photos and protected choices are excluded from board-wide replacement. Explicit card replacement can replace them. Saving a changed, unprotected card with AI consent stages a board preview before applying picture changes. Closing the preview discards that staged card edit.

Failures do not buy another generation automatically. New unresolved cards show a neutral placeholder. Existing asset-backed pictures remain after failed replacements. Parents may save an incomplete draft and resolve its missing pictures later. Child play never starts network work or replaces pictures.

## Sources and licensing

The committed metadata catalog is generated by `npm run pictures:update` from these fixed revisions:

- [Mulberry Symbols](https://mulberrysymbols.org/), `9cbab9f400c5de44e2bc58839cca07294aadb086` (v3.6.1): color illustrations by Steve Lee.
- [OpenMoji](https://openmoji.org/), `f9fc506a3f913be9897ab0181d611d4c910a4104` (17.0.0): black artwork by HfG Schwäbisch Gmünd and contributors.

The current app searches the color catalog. Outline entries and their style metadata remain readable for compatibility with earlier picture drafts; they are not offered as a user-selectable style.

Both artwork sets use [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/), permitting commercial reuse with attribution and applicable share-alike terms. Each asset retains its author, original source URL, license, and rasterization/padding notice. Credits are available in parent settings and card details. Original vector artwork remains available at each pinned source URL; adaptations must retain the artwork license. Catalog metadata is generated data; its importer owns documentation and revision updates.

The backend fetches only URLs from that catalog, disallows redirects and external SVG resources, validates image sizes, then rasterizes to PNG. It serves cached PNGs from its own asset endpoint. First use of an uncached symbol requires server internet access to GitHub. Saved boards need neither GitHub nor the home server for offline pictures.

## API and persistence

`/api/health` advertises picture protocol version 1 and catalog, analysis, and generation capabilities. Clients opt into extended board proposals with `pictureCapability: 1`. Legacy clients receive the original emoji proposal shape; clients talking to old servers retain the legacy flow.

Picture endpoints provide catalog search (`GET /api/pictures/search`), a chosen symbol (`GET /api/pictures/library/:id`), concept analysis (`POST /api/pictures/analyze`), durable jobs (`POST /api/pictures/jobs`, `GET /api/pictures/jobs/:id`, `POST /api/pictures/jobs/:id/cancel`), immutable PNGs (`GET /api/pictures/assets/:digest.png`), and final board review (`POST /api/pictures/review`). Schemas live in the shared core. Job identity binds a UUID to its payload and draft/card identity; changed payloads cannot reuse an ID. Cancellation stops queued work and attempts to abort active generation; a provider may already have charged for work underway. Restarted unfinished jobs require an explicit new attempt.

Library format v2 migrates v1 without changing board appearance. Native PNGs are separate from cropped JPEG photos; browser PNGs use IndexedDB v3. Downloads are digest-verified before references can be saved. Pruning runs at initial load and retains board and starter-draft assets; active drafts and undo are never pruned mid-session.

`OPENAI_IMAGE_MODEL` defaults to `gpt-image-2.5-flare`, using medium-quality 1024-square transparent PNG output. `AAC_IMAGE_GENERATION=false` disables new server-side generation. `PICTURE_CACHE_DIR` defaults to `.cache/pictures` for workspace development and `/app/data/pictures` in Docker, with its own persistent volume. Generation concurrency is two; the queue holds at most 48 pending cards. No model keys reach the client.

Generated pictures and their concept descriptions, completed job metadata, and hashed cache keys remain in the private server cache with no automatic eviction. Personal photos and their paths are not uploaded. Requests and provider response bodies are not logged. The service inherits the app's private-network, unauthenticated deployment boundary. Do not expose it as a public image-generation endpoint.

## Validation

`npm run check` and `npm run test:web` exercise mocked matching/generation, retention, migration, permissions, cancellation, failed downloads and offline play. `npm run eval:pictures` runs billable concept/library checks on six construction vehicles; add `-- --generate` to permit up to six new generated pictures. `npm run eval:pictures -- --animals --generate` creates a matching six-animal comparison: downloaded Mulberry library artwork, emoji, and deliberately requested AI illustrations. Results and a contact sheet are written under ignored `artifacts/picture-evaluation/`. The screenshot script captures all three sources with identical animal labels. Inspect the actual pictures: model review is fallible, and tests cannot establish a child's understanding or physical-device performance.
