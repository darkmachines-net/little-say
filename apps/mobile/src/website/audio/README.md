# Bundled starter speech

`manifest.json` maps the exact [starter vocabulary](../../../../../packages/core/README.md) to generated WAV digests. Files live in `apps/mobile/public/starter-audio/<digest>.wav`; Expo serves them in development and copies them into web exports. `starterAudio.ts` supplies URLs synchronously to the trial player. Audio bytes stay outside JavaScript and load only when a card is tapped. The manifest and recordings are committed product assets, so playback needs no API, key, account, or server cache. The shared player retains device-speech fallback for failed asset downloads or decoding.

The voice is pinned to the server's default Marin synthesis profile, with the prompt digest recorded in the manifest. Generate missing clips explicitly with `npm run speech:starters -- --generate`, using `AAC_OPENAI_KEY` or `OPENAI_API_KEY` in the process environment or root `.env`. This uses the existing transcript-checked Realtime synthesis path and may incur provider charges. Completed recordings are cached under `.cache/starter-audio/<prompt-digest>` for interruption recovery; partial runs leave the current manifest intact. A profile or prompt change prepares a new set. Review pronunciation before committing the assets.

`npm run speech:starters -- --check` verifies the complete vocabulary, active default profile, prompt digest, content hashes, and WAV format without credentials or network calls. Unit and browser coverage check the shipped files, exact text/language matching, real browser decoding with all API requests disabled, and device fallback after a failed download. Web builds include these WAVs in the app's offline shell; the public trial itself does not register a service worker. Native entry does not import this module or bundle these web-only recordings.
