# Parent and child interface

This directory owns app screens and shared controls for native and `/app` on web. `App.tsx` composes these flows with the library and service hooks. Platform-suffixed files adapt touch, photos, speech previews, and updates without changing the shared contracts. Use the [client services](../services/README.md) for persistence and network work.

## Visual and interaction conventions

- Use `theme.ts` and the shared [brand palette and assets](../../assets/brand/README.md): evergreen text, forest-green actions, warm cream backgrounds, white parent-control groups, and bright tiles. Use the system sans-serif font, compact bold titles, generous targets, and restrained borders/shadows.
- Keep the mountain decorative on Home, loading, and empty states. Keep play focused on the family's cards. Name actions directly, without slogans, decorative eyebrows, achievement systems, or progress metaphors. Explain data use, missing translations, and save failures where they affect a decision.
- `AppHeader` owns one white navigation row with a bottom border across parent pages. Home shows the mountain and app name; subpages show Back and their focused route title on the left, with top-level actions on the right. Optional context sits within the same row. Below 600 units the row is 64 units high and Home's mark is 36; larger screens use 76 and 56. Below 360 units, tighter padding and gaps leave room for compact route titles without shrinking action targets. Longer route titles may ellipsize, while their accessible labels keep the full title. Screens own safe-area insets. `PlayBoard` keeps its separate full-screen controls.
- `Dashboard` keeps **New board** (or **Resume draft**) full-width above the list through 620 units, with 16 units above and below it and no library heading. Wider viewports use a labeled floating action, 24 units from the bottom-right of the safe-area viewport. Bottom scroll padding includes its measured height, bottom inset, and 16 units of clearance so the final board can scroll above it, including with larger text.
- `Dashboard` puts the most recently used board in a spotlight. Every `BoardCard` preview starts play and carries a decorative play icon; Edit, Favorite, and More share one compact action group beside the title (below it in the wide spotlight). Cards omit tile counts and language metadata. First saving a manual or AI-created board, including a resumed draft, and duplicating a board count as use alongside play. Saving an unfinished creation draft does not. Favorites follow without duplicating the spotlight, then other boards, ordered by recent use. Favorites/use history are device metadata, independent of later board edits and undo. Board menus own deletion and missing-audio generation.
- `Sheet` and `ModalBackdrop` route outside taps through the same cancellation path as Close/Back. Inside gestures never dismiss. A gesture must start on the backdrop to dismiss, and underlying tiles must not activate.
- Keep controls inside system-bar and cutout insets on every edge. Each native modal owns a separate safe-area provider; backdrops may extend under bars, while headers, scrollable bodies, and fixed actions remain reachable after rotation and with gesture or three-button navigation.
- Preserve accessible labels, visible selected states, large touch targets, reduced-motion behavior, and keyboard focus restoration. Use [browser and device checks](../../../../tests/README.md) to validate both layout and interaction.

## Setup, editing, and play

`FirstTimeSetup` selects languages and optional starter boards. Persist completed drafts for resuming, show generated words, offer manual start when AI is unavailable, and never advance past a failed save or overwrite an existing library.

[`account/`](account/README.md) owns the headerless illustrated welcome, required sign-in, the status-first backup overview, and separate account management routes. Its README defines welcome layout, entry/restoration gates, navigation, provider confirmation, and credential lifetime.

**New board** opens an empty `BoardEditor` with direct **Add Card** and a compact `BoardAssistant`. Existing boards use the same editor. Its page heading is **Create** for unfinished drafts and **Edit** for saved boards, keeping the toolbar compact. **Add Card** and **Accept** share a manual-edit section immediately above the AI composer; Accept finishes editing and opens play after pending writes succeed. Saved boards have no idle status line; saving progress, write failures, and unsaved AI previews remain visible when relevant. There is no separate AI mode or conversation history UI. Clarification shows only the current question. Routes use `#boards/new` and `#boards/<id>/edit`; legacy `/ai` links remain readable. Back cancels remaining work, saves any usable preview, and flushes edits; failed saves/conflicts keep the editor open. Navigation is guarded during AI commits. Leaving an unfinished creation asks **Save draft**, **Discard**, or **Keep editing**, including an untouched workspace (Save is disabled without progress). Only Save writes the title, prompt, completed clarification history, and picture choices locally as `creationDraft`, outside playable/synced boards; reload restores that saved snapshot rather than unsaved edits. Discard clears it. Save/Discard failures keep the dialog open for retry, and page, browser, and Android Back are blocked during the write. The first saved manual card or completed AI turn consumes the saved draft atomically. Older saved creation sessions remain readable.

AI words appear on the canvas as soon as a validated proposal is available. New cards show their labels and a centered work indicator in the picture area while artwork is pending. Picture replacements fade the existing artwork beneath a centered replacement overlay. Labels stay fully visible; completion, fallback, and cancellation remove the overlay and restore full-opacity artwork. The composer reports observed queue, word/translation, picture lookup/generation/download, and save stages, with local picture readiness counts. Each verified picture fills its own tile without waiting for the rest. Each completed turn automatically merges and durably saves its changes as one normal toolbar **Undo** step; there is no Keep changes, Dismiss, or separate AI Undo action. **Stop request** saves the usable preview and cancels remaining work. Direct edits to a running preview also stop picture work and save the edited result. A resumed interrupted preview is saved automatically. Failed writes retain the visible result and offer **Retry saving AI changes**. The three-way merge in core `boardWorkspace` retains newer saved manual edits; overlapping changes require **Keep my edits** or **Use suggested changes**. Protected translation replacements retain their separate explicit review and save as another normal Undo step. A tile editor hands its saved words to the composer with selected-card scope enforced locally. Follow-ups use the latest visible board context, with bounded in-memory turns and no photo bytes or asset paths.

Saved direct edits, AI turns, and translations share chronological toolbar **Undo** and **Redo** controls. Undo retains the current board for Redo; a new edit or applied turn clears that board's remaining redo steps, including after a partial redo. Both controls are disabled during AI work, unresolved previews, playback startup, and dialogs. `services/useBoardHistory.ts` retains up to 20 steps per board in memory across navigation, clearing them on deletion/discard or app reload. Restoring history saves the restored content with a fresh revision without changing board recency. Redo also restores a newly created board after Undo returns it to an empty draft.

The composer contains editable text, Send, and contextual work/recovery controls. Example placeholders explain new-board, board-change, and selected-card requests; there are no suggestion pills or About AI button. Prompts use the system keyboard's dictation. Parents review and send the text; there is no app recording or dictation button. Native plugins disable microphone permissions and web hosting disallows page microphone access. Removing permissions from an already installed native app requires a replacement binary.

`BoardEditor` has three bounded regions: a fixed toolbar, a flexing canvas, and fixed manual-edit/composer controls. Controls sit beside the canvas on wide screens and short landscape windows, and below it on phones. Only the canvas and AI context scroll; neither is a scrolling ancestor of the prompt. The canvas receives the space left after the controls, without minimum canvas heights, percentage content heights, or measuring the controls to calculate its own height. The composer gets at most half the content height in the stacked layout (with a 96-unit floor for usable input/actions); its context scrolls before its input row shrinks. Multiline input has its own bounded scroll area.

The app root owns safe-area insets on all four edges. `BoardEditor` applies native keyboard **padding** only for overlap with that inset viewport, with the root top inset as its screen-coordinate offset. This works with both overlay keyboards and Android windows that already resize, without a cached initial-height baseline or a second safe-area wrapper. While the prompt's keyboard is open, title/status, manual-edit actions, and secondary toolbar controls collapse without moving the composer to a different parent or remounting its input. **Done typing** or Send dismisses the keyboard and restores the full layout. Short browser viewports use the compact layout while the prompt has focus. Preserve these boundaries when changing composer content; a reply, error, selected-card scope, or removed control must not change which region owns scrolling or keyboard avoidance. [Validation](../../../../tests/README.md#browser-scenarios-and-evidence) distinguishes native lifecycle checks, browser geometry, and real-device keyboard acceptance.

The canvas always shows the first effective language from the shared user profile and board subset, honoring fixed-language cards. Each tile editor starts in that primary language; choosing a translation changes only that card editor, and reopening starts in the primary language again. Board languages, pictures, audio preparation, duplicate, and delete live in the **Board settings** sheet opened by the top toolbar gear. Board language choices made during an AI preview follow the same three-way merge as direct card edits, including returning to inherited languages. Generated translations remain editable.

The canvas has no running card counter. Add Card remains available at 24 cards; requesting another opens an explanatory limit message without changing the board. Saving an already open new-card draft also checks capacity again. Tile ordering belongs in `TileEditor`; canceling an added card leaves the board unchanged. Accept requires at least one saved card and no pending suggestion.

User languages in Settings supply the play choices for all boards, including existing boards; adding a language in Settings never initiates translation. `BoardLanguages` directly toggles a nonempty subset of those languages, with no enabling switch, separate catalog or custom-tag entry. Selecting all resumes inheritance, including future additions. Removed profile languages are ignored in subsets; if none remain, play uses the user default. Saved words and audio remain available if the language is selected again. Legacy `playLanguages` records generation context; `playLanguageSubset` alone restricts play.

Opening shared language preferences retains the current editor as the Settings caller. Browser Settings URLs omit the board hash; selection stays intact while those pages are open so **Back to board** restores the same editor and its language subset.

Closing the board language panel (Done, Close, backdrop, system Back, or the Settings link) starts [automatic missing-translation preparation](../services/README.md#board-translations). It closes immediately; progress, cancellation and retry appear in the editor, with no separate preparation/review step. Card labels, spoken words and fixed-language behavior belong to the individual card editor. New manual and starter cards follow the board even with only one user language; legacy fixed cards keep their words until individually changed. Audio follows each language's AI/device voice choice and prepares automatically after translated words are saved; downloaded clips remain usable offline. The language panel has no audio controls.

`PlayBoard` prioritizes the grid. Boards open unlocked. The compact header reserves fixed 48-unit slots for Back on the left and the lock icon on the right, with the title and optional language toggle between them. Locking hides Back without collapsing its slot. Lock status and hold progress overlay the top safe-area inset without taking a grid row or intercepting touches. The compact status sits at the trailing edge to avoid central camera cutouts; the full instruction remains available to assistive technology. When the top inset is smaller than 24 units, status shares the title's header slot and progress follows the header's top edge. Play and editor use the shared measured, ordered rectangles in core: balanced rows, soft preference for square cards, and 44-unit minimum targets. Play fills the space without scrolling; if it cannot fit, explain the need for more room and recover after resize. Reflow cancels contacts tied to old geometry without restarting speech or reordering cards.

Tile speech feedback is a green outer outline and speaker badge; brief touch feedback is an amber inset outline. Both may appear without changing geometry. The parent hold uses one gesture state and monotonic clock for its one-second threshold and progress. Movement, extra touches, cancellation, backgrounding, or board interaction reset its timer and feedback together. Holding unlocks automatically at one second without leaving the board or showing a dialog; a separate press of Back opens the editor. Android system Back uses the same editor-return action while unlocked and is blocked only while locked. Lock changes do not interrupt speech. Early release cancels. The lock control stays mounted and ignores the completing contact's release/click so only a fresh tap can relock. Preserve the cancellable one-second assistive alternative.

Photos use native picker/cropper or the browser cropper. Later adjustment supports direct drag/pinch and fine zoom, previews the actual square region, and preserves it across views and rotation. Canceling leaves the original intact; duplicates have independent framing. Native adjustments start from the system crop, so recovering cropped-out content requires choosing the original again.

## Picture controls

New boards use the core Automatic picture defaults. `PicturePreferences` edits draft/board choices; `BoardPictures` and `CardPictures` provide deliberate board/card changes. **Board settings → Pictures** sets empty-board defaults or stages picture updates on the accepted board or suggestion. Use one labeled source selector with vertically expanded descriptions and current-value guidance, separate protection switches, and explicit inherited card source. Do not restore wrapping chips, the legacy consistency switch, or a style selector. New artwork uses simple color; existing artwork stays readable.

Automatic keeps accurate, unambiguous emoji, uses the library for gaps, and generates only remaining gaps. Library only and Emoji only never generate. Completed drafts go to save/refinement without illustration upsells. Parents may deliberately choose AI illustrations and **Improve pictures** / **Restyle board**, with preview and explicit apply. Card options include library search, description, overrides, and **Keep this picture**. Credits belong in parent controls.

Show queued, active, ready, and fallback cards distinctly; animate only active work and honor reduced motion. Stream completed downloads into a reviewable draft, support stop/retry, and save only on explicit apply. Retain useful emoji or previous images on failure with one concise fallback summary. Contain illustrations so identifying features remain visible; photos retain their crop treatment. Play never initiates picture work. [Picture draft services](../services/README.md#picture-drafts) define protection, revision checks, and download ownership.

## Settings

`SettingsScreen` is a grouped navigation page with **Preferences** and **Help**. `SettingsPage` owns the surrounding page chrome; route parsing and history live in `services/settingsRoute.ts` and `useSettingsRoute.ts`.

| Route under `/app/settings` | Responsibility |
| --- | --- |
| root | Overview and current language summaries |
| `/languages` | One to six shared languages; direct search with a result dropdown, divided rows, removal under Edit, and one default selector |
| `/screen-guidance` | Platform-specific Guided Access/screen-pinning links or browser guidance |
| `/updates` | Installed native update check/download/restart; disabled in development or when updates are unavailable |
| `/privacy` | Storage, backup, AI processing, photos, dictation, retention disclosures, and picture credits |
| `/about` | Selectable running version, environment, and available native build/update details |

`LanguageProfileEditor` shares the simple-list controls with first-time setup. Search accepts names, regions, and language tags, excludes selected choices, and closes after adding. Web uses a floating result dropdown with Enter, Escape, and keyboard focus dismissal; native expands results inside the parent's touch bounds. Region names replace raw tags where Intl supports them. **Edit** reveals removal controls, retaining one language; removing the default uses the first remaining choice. The single default control uses a browser select on web and a cancellable option sheet on native.

Voices and Pictures have no app-wide settings pages. Speech and new pictures use the defaults described in [client services](../services/README.md#speech); existing board/card picture choices remain editable. Retired `/voices`, `/voices/:language`, and `/pictures` links open the Settings overview.

Browser pages support direct links, refresh, history, and offline fallback. Native uses a stack and Android Back. Direct links without app-owned history return to their logical parent. Play keeps its exit protection; App routes require sign-in, including Settings. Preferences save individually through durable library commits. Controls/navigation wait for a write; failure preserves the previous value and offers Retry saving. Preference patches preserve boards, playback, and cached account data; there is no overview-level save action.

Native manual updates wait for pending local writes before restart. Leaving the page cancels further actions, though an active download may finish for a later launch. Web retains its service-worker update banner. Settings never edits the service origin. Use OS Guided Access or Android screen pinning for system containment; app controls cannot suppress system navigation.

`AboutSettings` reads local metadata through [`appInfo`](../services/README.md#installed-app-information), so identifying the installed release works offline. Version describes the running bundle; installed version and build number describe the native binary and may differ after an app update. Values are selectable for support requests.
