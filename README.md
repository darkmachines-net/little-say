## iOS Expo Go completion and lifetime assessment

Generated speech is persisted as a WAV file under native document storage and looked up by speech/language; speechLibrary.asset is a stable instance function. The native adapter creates an explicitly owned player, subscribes before play(), waits for audio mode, and suppresses late events using its active flag. It uses createAudioPlayer rather than an automatically releasing React hook.

In the inspected iOS vendor source, play() registers the AVPlayerItemDidPlayToEndTime observer; a matching current/queued item emits didJustFinish=true. Periodic status emits false. The hybrid completion path removes the listener/player before notifying the queue, and the queue clears active state or advances the newest pending card. The PR changes none of this completion path. If the end notification is absent/not forwarded, the already-loaded clip waits for the existing 20-second watchdog; this error-field patch cannot repair that without an error event. A cleanup exception before done() is another existing hypothesis to instrument, not an observed failure. No speculative source change is requested.

Additional lifecycle detail: the iOS remove() bridge removes the player from its registry asynchronously; full native observer/time-observer teardown is attached to shared-object release. The JS active flag/listener removal guards stale deliveries, and current QA found no evidence that this lifetime behavior caused the report. On the affected iPad, distinguish end-event delivery, listener cleanup and queue settlement with one playback identity, including whether the stuck state survives 20 seconds and whether a reload/interruption occurred.
